# apps/web

대화 웹(Next.js App Router)이다. 대화 흐름의 판단은 모두 서버에 있고, 웹은 화면과 입력과 진행 표시만 맡는 얇은 클라이언트다. 서버의 응답을 표시할 뿐 자체 대화 상태를 만들지 않고, 모델을 직접 부르지 않으며, API 키를 두지 않는다.

## 규칙

- **색은 토큰으로만 쓴다.** 색 값(hex, `rgb()`, `hsl()`)은 `apps/web/app/globals.css` 의 테마 블록과 `theme/` 밖에 두지 않는다. 컴포넌트와 화면은 Tailwind 가 그 변수를 가리키는 토큰 클래스만 쓴다. 테마는 셋(`hanji` 기본, `night`, `ink`)이고 라이트·다크는 OS 설정을 따르므로, 새 색이 필요하면 토큰을 더하고 세 테마 × 라이트·다크 여섯 값을 함께 둔다. 테마는 쿠키에만 두고 서버나 DB 에 두지 않는다(기기 설정이다).
- **사용자에게 보이는 글자는 `i18n/` 에만 둔다.** 컴포넌트와 화면에 한글이나 영문 문구 리터럴을 넣지 않고 ko·en 카탈로그의 키로 넘긴다. 공용 컴포넌트(`components/ui/`)는 글자를 품지 않고 호출하는 쪽이 문구를 props 로 준다. ko·en 의 키 일치는 `Messages` 타입이 컴파일 때 보장하고, 함수형 문구의 자리 표시자는 양쪽이 같아야 한다. ko 에서 이름 뒤 조사(와/과, 는/은, 를/을, 이/가)는 붙여 쓰지 않고 `i18n/` 의 조사 도우미로 고른다.
- **금지어.** 사용자에게 보이는 글에 상담, 치료, counseling, therapy, therapist, counselor, treatment, clinical, diagnose, cure, patient 를 쓰지 않는다(ADR-0003). 예외는 둘뿐이다: 공공 기관 이름 "자살예방상담전화", 그리고 면책 문구의 부정형("치료를 대신하지 않아요"). 카탈로그 테스트가 이것을 본다. 위기 안내의 번호(109, 1577-1366)는 서버 `GET /v1/safety/resources` 의 고정값과 같아야 하고 테스트가 맞춰 본다.
- **공개 경로.** `/help` 는 인증 없이, 서버가 내려가 있어도 열린다. 인증 가드에 넣지 않고 서버 호출을 두지 않는다. 제품 사용자의 모든 화면의 머리에 도움 알약, 바닥에 위기 띠와 면책이 있다. 관리자 화면(`/admin`)만 도움 알약과 위기 띠를 두지 않는다(관리자는 제품 사용자가 아니다). 어느 경로가 어떤 머리·바닥을 갖는지는 `components/layout/chrome.ts` 표 한 곳에서 정한다.
- **위기 안내를 약하게 만들지 않는다.** 위기 카드와 `/help` 의 번호 줄과 "당장 위험하다면 112 또는 119" 줄은 뺄 수 없다.
- **삽화는 `public/illustrations/<테마>/` 에 WebP 두 크기만 둔다.** PNG 원본과 프롬프트는 레포 밖(로컬 `outputs/design/`)이다. 삽화는 장식이라 `alt=""` 이고 뜻을 전하는 글은 늘 이미지 밖에 둔다. 글자, 얼굴, 실존 인물, 상표가 든 이미지는 넣지 않는다. 모든 삽화 틀에는 그라데이션 바탕을 깔아 이미지가 없어도 모양이 유지되게 한다.

## 테스트 방침

- 테스트는 실제로 깨지는 것에만 둔다: 토큰 밖의 색, 두 언어 카탈로그의 어긋남(금지어, 자리 표시자, 조사), 상태 전환의 논리(버튼의 busy·disabled, 모달의 포커스 복귀, 토스트의 오류 머묾, 진행 표시의 계산), 테마 값 해석, 테마 대비(세 테마 × 라이트·다크의 대비 쌍이 본문 4.5:1, 경계 3:1 을 넘는가).
- 순수 표시 컴포넌트와 스냅샷 테스트는 두지 않는다. 테마별 화면 확인은 QA 가 한 번 한다.
- 레포 검사가 `apps/web` 의 hex 색 리터럴과 컴포넌트의 한글 리터럴을 본다. 지금은 경고이고 재디자인이 끝나면 실패로 올린다. 검사를 지나려고 예외 경로를 늘리지 않는다.
