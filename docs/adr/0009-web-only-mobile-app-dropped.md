# 제품은 웹으로만 만든다. Flutter 모바일 앱과 그 API 는 접는다

## 맥락

Beside Pet 은 Flutter 앱(iOS, Android)과 NestJS API 로 시작했다. 2026-03-26 중단 때 앱은 MVP 의 85에서 90% 쯤이었고, 스토어 제출, 결제(RevenueCat), 미국 리전 운영, 법률 검토가 남아 있었다(DEV-2026-03-26-project-pause). 그 뒤 웹 챗봇(Next.js 웹과 별도의 NestJS API)을 새로 만들어 AWS 에 올렸다. 두 제품은 코드도 인증도 LLM 도 달랐다. 2026-09-29 모노레포를 만들며 모바일 앱과 그 API 를 `archive/` 로 옮겨 개발과 CI 와 배포에서 뺐고, 2026-10-16 사용자가 모바일 앱을 접고 웹으로만 운영하기로 했다. 같은 날 AWS 운영 자원도 모두 내렸다.

## 결정

- 제품은 상담 웹(`apps/web`), 소개 사이트(`apps/landing`), API(`apps/api`)뿐이다. 모바일 앱, 앱스토어, 푸시 알림, 기기 기반 제한, 생체 인증은 하지 않는다.
- 모바일 앱과 그 API 의 코드는 이 레포에 들이지 않는다. 그 시기의 결정과 실측은 ADR 과 개발 일지로만 옮기고, 원문은 `docs/research/legacy/` 에 로컬로 둔다.
- 웹 클라이언트는 얇다. 화면, 입력, 진행도 표시만 하고 상담 흐름, 다음 질문, 모델 호출, API 키는 모두 서버에 둔다.
- 지금은 운영 환경이 없다. 다시 올릴 때는 `infra/` 코드로 만든다.

## 버린 것

| 안 | 이유 |
|---|---|
| 모바일 앱을 이어서 출시 | 남은 일(스토어 제출, 인앱 결제, 미국 리전, 법률 검토, 테스트 0%)이 많았고, 웹과 두 벌의 제품을 유지할 여력이 없다 |
| 모바일 앱을 웹뷰나 PWA 로 감싸 스토어에 올림 | 지금 필요한 것이 아니다. 웹이 자리를 잡은 뒤 다시 볼 일이다 |
| 모바일 코드를 비활성 폴더로 레포에 유지 | 검색과 의존성 작업에 섞인다. 문서로만 남긴다 |

## 결과

- 모바일 시기의 기능 상당수(AI 위로 편지, 메모리 스페이스, 사진, 일일 기분 체크인, 음성 메시지, 구독)는 웹에 없다. 다시 들일 때는 새 PRD 로 다룬다.
- 데모와 리뷰가 URL 하나로 된다.
- 모바일 시기의 미국 시장 전제(ADR-0001), 다중 모델 구성(ADR-0011), 요금제(ADR-0013)는 함께 효력을 잃었다.

## 근거

- 새 레포의 `CLAUDE.md` 첫 문단("모바일 앱은 접었고 웹으로만 운영한다")과 "지키는 선"(운영 환경 없음).
- 옛 모노레포의 web-only ADR(2026-09-29, 레포 밖 `docs/knowledge/adr/2026-09-29-web-only-monorepo.md`): 앱은 더 이상 개발하지 않고 `archive/` 에 둔다.
- `apps/web/docs/ARCHITECTURE.md` 1절과 2절(얇은 클라이언트, 웹을 고른 이유).
- `docs/research/2026-10-16-deploy-analysis.md`: 같은 날 EC2, RDS, CloudFront, ECR 삭제.
- `docs/research/legacy/PROJECT_PAUSE_2026-03-26.md`: 중단 시점의 모바일 완성도와 남은 일.
