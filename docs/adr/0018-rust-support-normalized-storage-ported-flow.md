# Rust 서버의 대화(support)는 저장만 다시 설계해 일어난 일을 행으로 두고, 흐름과 상수와 프롬프트와 RAG 와 SSE 는 TS 그대로 옮기며, 모델 호출에 시간 제한을 둔다

## 맥락

ADR-0015 는 엔드포인트의 겉을 먼저 옮기고 기능의 속은 PRD 마다 포팅과 재설계 중에 고르라고 했다. #10 이 대화 기능(`support`)의 속을 채운다. TS API 는 세션 하나를 `sessions` 행의 JSONB 문서(애도 프로필, 전사, 지지 계획, 종료 요약, 마음 리포트)와 `turn_analyses` 의 칸으로 저장했다(ADR-0006 "저장하는 것"). 루트 `CLAUDE.md` 의 "데이터를 두는 원칙"은 일어난 일을 일어난 그대로 적고, 계산할 수 있는 값은 저장하지 않으라고 한다. 지금 운영 DB 가 없어(2026-10-16 자원 내림) 옛 저장 모양과의 호환은 제약이 아니다. #9 는 모델 공급자의 reqwest 클라이언트에 시간 제한이 없다는 것을 남겨 두었다. 응답하지 않는 로컬 모델(Ollama)에 턴이 무기한 걸릴 수 있다.

## 결정

1. **저장은 다시 설계한다.**
   - 전사는 `messages` 행(세션, 순번, 역할, 본문, 그때의 과제, 시각)이다. 턴 분석은 지금처럼 `turn_analyses` 행이다.
   - Planner 의 지지 계획과 Summarizer 의 종료 요약은 프로필과 전사·분석에서 결정론적으로 나오는 파생값이라 저장하지 않고, 응답 때 규칙으로 다시 구한다. 진행률도 과제에서 구한다.
   - 마음 리포트는 모델이 쓴 사실이므로 `sessions.report`(JSONB)에 저장한다. write-once 는 ADR-0008 그대로다. 애도 프로필은 세션 행의 JSONB 다.
   - `sessions` 의 `history`, `plan`, `summary` 칸은 새 마이그레이션으로 지운다.
   - 저장은 세션 행·메시지·분석을 한 트랜잭션의 upsert 로 쓴다. 같은 id 의 세션이 다른 소유자의 것이면 아무것도 쓰지 않고 거절한다(소유자 불일치 가드, 흐름에서는 403).
   - 삭제는 한 트랜잭션으로 `turn_analyses` → `messages` → `sessions` 순서다.
   - 응답의 모양은 바뀌지 않는다(웹이 읽는다).
2. **흐름과 상수는 옮긴다.** 한 턴은 안전 확인 → 과제 전이 → 지식 검색 → 발화 → 턴 분석 → 저장이다(ADR-0005). 위기 판정은 키워드 ∪ 모델이고, 위기면 발화 모델을 부르지 않고 `safety` 의 고정 문구로 닫으며 지원 수준은 내려가지 않는다(ADR-0004). 깊이 게이트의 상수(3, 2, 5), 진행률 (task-1)/4, 세션 잇기(직전 세션의 프로필과 도달 과제, 클로징이면 과제 1, 요약과 전사 꼬리 6개), 목록 20개, 발화 320 토큰과 리포트 900 토큰, 관리자가 남의 세션을 보는 지금 동작(ADR-0006), 오류 문구는 TS 그대로다.
3. **프롬프트와 RAG 는 옮긴다.** 발화·리포트·위기 판정 프롬프트는 TS 문구 그대로이고, 지식은 `rag-knowledge/grief-knowledge.json` 을 기동 때 읽어 과제별 2개를 고른다(ADR-0014). 모델이 바뀌면(ADR-0010) 그때 다시 맞춘다.
4. **전송은 SSE 를 유지한다.** `meta` → `token`* → `done` 이고, 위기도 `meta` 뒤 고정 문구를 토큰 하나로 보낸다. 웹(`apps/web`)은 건드리지 않는다.
5. **모델 호출에 시간 제한을 둔다.** 흐름이 받는 모델을 감싸, 대화가 부르는 모든 호출(위기 판정, 발화, 리포트)에 건다. `generate` 는 호출 전체에 120초, `stream` 은 조각 사이(첫 조각 전 포함)에 60초다. 넘기면 종류만 로그에 남기고 500 이다. 위기 판정이 제한을 넘기면 판정 실패와 같이 키워드 결과로 대신한다(ADR-0004 의 폴백). 공급자의 HTTP 클라이언트(`llm`)는 고치지 않았다.

## 버린 것

| 안 | 이유 |
|---|---|
| TS 의 JSONB 문서 저장을 그대로 옮김 | 전사가 문서 안에 묻혀 SQL 로 셀 수 없고, 계획·요약 같은 계산값이 사실처럼 저장된다. 운영 데이터가 없어 지금 바꾸는 비용이 가장 작다 |
| 계획과 요약도 행으로 저장 | 같은 입력에서 늘 같은 값이 나온다. 저장하면 규칙을 고쳤을 때 옛 값과 새 규칙이 어긋난다 |
| 마음 리포트를 열 때마다 생성 | ADR-0008 의 이유(느림, 내용이 바뀜, 비용)가 그대로다 |
| 전송을 바꿈(웹소켓, 자연스러운 대화 UI) | 웹과 함께 바꿔야 한다. 다음 PRD 로 미룬다 |
| 시간 제한을 reqwest 클라이언트에 둠 | 그 파일은 #10 의 범위 밖이고, 흐름에서 감싸면 공급자와 상관없이 위기 판정까지 한 곳에서 막는다. 클라이언트의 연결 제한은 모델 PRD 에서 더할 수 있다 |
| 제한을 짧게(예: 30초 전체) | CPU 의 로컬 모델이 리포트 900 토큰을 쓰거나 모델을 처음 올리는 시간을 끊는다. 제한의 목적은 걸린 연결을 끊는 것이지 느린 답을 끊는 것이 아니다 |

## 결과

- 이 글은 ADR-0006 의 "저장하는 것" 가운데 세션의 저장 모양(JSONB 의 전사, 지지 계획, 종료 요약)을 대신한다. 세션 행에는 진행 상태 칸, 애도 프로필, 마음 리포트가 남고 전사는 `messages` 행이다. ADR-0006 의 나머지(본인만 접근, 대화 삭제의 연쇄, 계정 삭제의 빈자리)는 그대로이고, 연쇄 삭제의 대상에 `messages` 가 더해졌다.
- 단계 도달률과 턴 수를 `messages`, `turn_analyses` 에서 SQL 로 셀 수 있다.
- 스트림 턴은 따로 도는 작업에서 돌아, 받는 쪽이 떠나도 턴을 끝까지 마쳐 저장한다. 모델 스트림이 도중에 실패하면 `done` 없이 끊고 그 턴은 저장하지 않는다(TS 와 같다).
- 세션 시작은 TS 처럼 인사 전에 세션을 한 번 저장한다. 인사 생성이 실패하면 전사가 빈 세션이 목록에 남는다.
- 같은 사용자가 이미 쓴 세션 id 로 다시 시작하면 TS 처럼 그 세션을 덮어쓴다. 다만 메시지는 순번 upsert 라, 새 전사보다 긴 옛 메시지가 남을 수 있다. 클라이언트가 새 id 를 만들므로 지금은 받아들인다.
- 위기 판정이 걸리면 턴이 최대 120초 늦어진 뒤 키워드로 판정된다.
- 리포트 프롬프트는 #15 에서 TS 문구를 한 군데 벗어났다. `@@emotions` 바로 뒤 첫 줄에 감정 낱말 2~4개를 출력 언어로 쉼표로 적게 하고, 파서가 그 줄을 떼어 리포트 JSON 의 emotions 구역 `tags` 로 둔다. 낱말 줄의 모양이 아니면(쉼표 없음, 문장 부호, 20자 넘는 항목) 떼지 않아 그 전에 저장한 리포트와 옛 출력은 `tags` 없이 그대로다.
