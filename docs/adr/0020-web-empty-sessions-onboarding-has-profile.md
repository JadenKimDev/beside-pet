# 세션이 없으면 온보딩으로 보내고, `/me` 는 남아 있는 세션의 유무(`hasProfile`)만 준다

## 맥락

재디자인 안은 대화를 모두 지운 사람에게 온보딩이 아니라 "아직 나눈 이야기가 없어요" 빈 상태를 보이려 했다. 처음 온 사람과 다 지운 사람을 가르려면 "이 계정이 대화를 시작한 적이 있는가"를 서버가 알아야 한다. 그런데 ADR-0006 은 대화 삭제를 연쇄 삭제로 정했고 지운 대화의 흔적을 남기지 않는다. 남아 있는 행으로는 "시작한 적이 있다"를 셀 수 없다.

## 결정

- `GET /v1/auth/me` 는 `hasProfile: boolean` 만 더한다. 뜻은 **지금 남아 있는 세션이 하나라도 있는가**다. 대화를 모두 지우면 false 다.
- 웹은 세션 목록이 비어 있으면 지금처럼 온보딩으로 보낸다. 처음 온 사람과 다 지운 사람을 가르지 않는다. 다 지운 사람은 온보딩을 다시 거치며 새 프로필을 만든다.
- "아직 나눈 이야기가 없어요" 빈 상태는 온보딩에서 돌아왔는데 목록이 비어 있는 경우에만 쓴다. 다 지운 뒤의 짧은 순간을 위한 화면으로 쓰지 않는다.

## 버린 것

- `everStarted: boolean`(시작한 적이 있는가). 세려면 지운 세션의 흔적(계정별 표시, 삭제 기록, 지우지 않는 행)을 남겨야 하고, 이는 ADR-0006 의 "삭제는 흔적 없음"과 어긋난다. 빈 상태 하나를 위해 삭제의 약속을 약하게 만들지 않는다.
- 웹 쪽에서 기기에 "시작한 적 있음"을 기억하는 방법. 기기와 브라우저마다 달라지고, 지운 사실을 기기에 남기는 것이라 같은 이유로 버린다.

## 결과

- 다 지운 사람은 온보딩을 다시 본다. 재디자인 안의 뜻과 다르지만 삭제의 약속이 먼저다.
- 목록 화면의 온보딩 분기는 바뀌지 않는다. `hasProfile` 은 서버가 주지만 웹의 분기는 지금처럼 목록이 비었는지로 정한다.
- 이 결정을 뒤집으려면 ADR-0006 을 먼저 다시 정해야 한다.

## 근거
