# 모델 호출은 본문 없이 사실로만 DB 에 기록하고, 집계와 비용은 뷰로 하며, 프롬프트는 역할별 `x.y.z` 버전을 갖는다

## 맥락

모델 호출의 사용량(`llm::UsageRecord`)은 프로세스 메모리에만 쌓여 재시작하면 사라졌고, 토큰과 비용만 있어 어떤 역할(발화, 위기 판정, 리포트)의 호출인지, 얼마나 걸렸는지, 실패했는지를 알 수 없었다. 대화 모델을 Claude Haiku 에서 Ollama 모델로 바꾸려면(ADR-0010) 같은 역할과 같은 프롬프트에서 두 모델을 비교할 수 있어야 한다. 비용 단가는 코드(`llm/pricing.rs`)에 있어 모델을 더할 때마다 배포가 필요했고, 호출마다 계산한 비용을 기록에 실어 둔 채였다.

프롬프트 문구는 TS 의 것을 그대로 옮겼지만(ADR-0018) 버전이 없어, `pnpm chat:eval` 의 실측 결과가 프롬프트 수정 때문인지 모델 때문인지 구분할 수 없었다.

## 결정

- **호출마다 사실 한 행을 `llm_calls` 에 남긴다.** 완료 시각, 공급자, 모델, 역할(`reply`, `crisis`, `report`), 프롬프트 버전, 세션 id(있으면), 입력·출력 토큰(실패면 비움), 걸린 시간, 스트리밍이면 첫 글자까지의 시간, 결과(`ok`, `error`), 오류 종류. Rust 서버에서 모델을 부르는 곳은 이 세 역할뿐이다(지지 계획과 종료 요약은 규칙이다, ADR-0018). 프롬프트와 응답 본문은 저장하지 않는다(ADR-0006, 루트 `CLAUDE.md` "읽지 않는 것").
  - 오류 종류의 뜻(#22, 2026-10-21): `timeout` 은 라우터의 시간 제한(호출 전체 120초, 스트림 조각 사이 60초)을 넘긴 것, `cancelled` 는 끝나기 전에 부른 쪽이 기다리기를 멈춘 것(연결 끊김, 사용자의 중단)이다. 시간 제한은 라우터(`llm/router`)가 공급자 호출을 감싸 건다.
- **라우터(`llm::ModelRouter`)가 재고 기록한다.** 부르는 쪽은 요청에 맥락(역할, 프롬프트 버전, 세션 id)만 싣고, 걸린 시간과 성공·실패는 라우터 한 곳이 잰다. 공급자는 모른다.
- **기록 실패는 대화를 막지 않는다.** Postgres 싱크는 채널로 넘겨 따로 도는 작업이 쓰고, 쓰기 실패는 종류만 로그에 남긴다.
- **계산한 값은 저장하지 않는다.** 비용은 단가 테이블 `model_prices`(모델, 입력·출력 USD/MTok, 적용 시작일)와 토큰을 곱하는 뷰이고, 날짜·모델·역할·버전별 집계와 p50·p95 는 뷰와 쿼리다. 단가는 `model_prices` 한 곳에만 두고 코드의 단가표는 지운다. 모델을 더하면 마이그레이션으로 단가 행을 더한다.
- **계측은 별도 기능 `metrics` 이고 본문을 내보내지 않는다.** 관리자 전용 API 는 집계만 돌려주고, 관리자의 평시 전사 열람을 막는 ADR-0006 의 목표를 바꾸지 않는다. 기능 방향은 `metrics → identity` 다.
- **프롬프트는 역할별 `x.y.z` 버전을 갖고 `0.1.0` 부터 시작한다.** 발화, 리포트, 위기 판정의 프롬프트 모듈이 각각 버전 상수를 갖고, 지금의 문구(ADR-0018 "TS 문구 그대로")가 `0.1.0` 이다. 올리는 기준:
  - major: 실측 기준선을 새로 잡아야 하는 변경. 역할, 흐름, 안전 규칙이 바뀜.
  - minor: 같은 기준선에서 비교할 수 있는 문구 변경.
  - patch: 오탈자와 다듬기.

  프롬프트를 바꾸는 커밋이 같은 커밋에서 그 역할의 상수를 올린다. `pnpm chat:eval` 의 실측은 같은 버전끼리 비교한다. 목적은 무분별한 프롬프트 수정과 실측 피드백을 구분하는 것이다.

## 버린 것

| 안 | 이유 |
|---|---|
| 메모리 싱크를 두고 관리자 API 가 프로세스의 것을 읽음 | 재시작하면 사라지고, 모델 비교는 며칠에 걸친다 |
| 호출 기록에 비용을 계산해 저장 | 단가가 바뀌면 옛 행과 새 단가가 어긋난다. 토큰과 단가에서 늘 같은 값이 나오므로 뷰다(루트 `CLAUDE.md` "데이터를 두는 원칙") |
| 단가를 코드와 DB 양쪽에 둠 | 같은 사실이 두 곳에 있으면 어긋난다. DB 한 곳이면 모델을 더할 때 배포가 필요 없다 |
| 프롬프트 본문의 해시를 버전으로 씀 | 어떤 변경이 비교 가능한지 사람이 판단한 것이 아니라서, 실측을 가를 기준이 되지 못한다 |
| 전체 프롬프트에 버전 하나 | 역할마다 바뀌는 때가 다르다. 위기 판정 문구를 다듬었다고 발화 실측 기준선을 버릴 이유가 없다 |
| 기록을 호출 경로 안에서 동기로 씀 | DB 가 느리거나 멈추면 대화가 같이 멈춘다. 기록은 부수 작업이다 |
| 프롬프트와 응답 본문도 기록해 품질 분석에 씀 | ADR-0006 의 선을 넘는다. 품질 실측은 QA 계정의 `pnpm chat:eval` 전사로 한다 |

## 결과

- 대화 한 턴에 `llm_calls` 행이 생기고(위기 판정이 모델까지 가면 둘), 관리자는 기간별로 모델·역할·버전의 호출 수, 토큰, p50·p95, 첫 글자 시간, 실패율, 비용을 본다. 화면은 backoffice(#5)가 만든다.
- `llm/pricing.rs` 와 그 테스트가 사라지고 비용 테스트는 뷰를 보는 DB 테스트가 된다.
- 프롬프트를 고치면서 상수를 올리지 않으면 실측 비교가 어긋난다. 이 규칙은 `apps/server/CLAUDE.md` 에 적는다.
- #18 이 발화 지시문을 바꾸므로, 먼저 닫히는 쪽이 `0.1.0` 을 두고 뒤에 닫히는 쪽이 올린다.
