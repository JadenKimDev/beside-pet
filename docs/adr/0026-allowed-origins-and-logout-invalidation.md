# 서버의 CORS 는 허용 출처 목록이고 production 에서 필수이며, 로그아웃은 시각 하나로 그 전의 토큰을 무효로 만든다

## 맥락

서버의 CORS 는 요청의 origin 을 그대로 돌려주고 자격증명을 허용했다. 옛 TS API 의 `origin: true, credentials: true` 를 그대로 옮긴 것이다(ADR-0015). 어떤 사이트든 사용자의 쿠키를 실어 API 를 부를 수 있다는 뜻이다. 로그아웃은 쿠키만 지웠고, 토큰(JWT, 7일)은 만료까지 살아 있어 복사된 토큰은 로그아웃 뒤에도 쓸 수 있었다.

production 은 CloudFront 기본 도메인 하나에 있고(ADR-0023), 운영 화면은 Next 서버가 API 를 대신 불러 브라우저가 서버에 직접 닿지 않는다(ADR-0024). 그래서 브라우저에서 서버를 직접 부르는 출처는 대화 웹 하나다.

## 결정

- **CORS 는 `ALLOWED_ORIGINS`(쉼표로 나눈 출처 목록)로 좁힌다.** 목록 안 출처는 그 출처를 그대로 돌려주고 `Access-Control-Allow-Credentials: true` 다. 목록 밖 출처에는 `Access-Control-Allow-Origin` 을 내지 않는다.
- **`APP_ENV=production` 이면 `ALLOWED_ORIGINS` 가 필수이고, 없으면 이유를 적고 기동하지 않는다.** ADR-0021 의 "없으면 뜨지 않는다"와 같은 태도다. 값은 SSM 파라미터의 환경 파일에 사용자가 더하고, CloudFront 기본 도메인 하나다. sandbox 에서 없으면 지금처럼 origin 을 그대로 돌려준다(개발 편의. 포트가 자주 바뀐다).
- **로그아웃은 `accounts.tokens_valid_from` 에 `now()` 를 적고, 인증 추출기는 토큰의 `iat` 가 그 시각보다 앞이면 401 을 낸다.** 기존 행은 NULL 이고 제한 없음이다. 토큰 저장소와 블랙리스트는 두지 않는다. "마지막 로그아웃 시각"이라는 사실 하나로 충분하고, 데이터를 두는 원칙(일어난 일만 적고 가공하지 않는다)에 맞다.
- **비교는 초 단위다.** JWT 의 `iat` 가 초 단위라 `iat < tokens_valid_from` 을 그대로 쓰면 로그아웃과 같은 초에 발급된 새 로그인 토큰이 막힌다. `iat 초 < tokens_valid_from 초`(내림)로 비교해 같은 초의 새 로그인은 산다. 테스트가 이 경계를 본다.
- 엔드포인트의 겉(`POST /v1/auth/logout` 204, `GET /v1/auth/me` 401 문구)은 바꾸지 않는다(ADR-0015).

## 버린 것

- **발급한 토큰을 저장하고 로그아웃 때 지우는 방식(토큰 저장소).** 로그인마다 행이 늘고, 만료 정리가 필요하며, 지금 필요한 사실(이 시각 전의 토큰은 무효)보다 많은 것을 저장한다.
- **로그아웃한 토큰의 블랙리스트.** 토큰 본문이나 해시를 DB 에 두어야 하고, 만료까지 지워지지 않는 행이 쌓인다. 계정당 시각 하나가 같은 효과를 낸다.
- **토큰에 세션 번호를 넣고 계정의 세션 번호를 올리는 방식.** 효과는 같지만 토큰 모양과 계정 칸이 둘 다 늘고, "언제 로그아웃했는가"라는 사실이 남지 않는다.
- **sandbox 에서도 `ALLOWED_ORIGINS` 필수.** 워크트리마다 포트가 달라(3001, 3011, …) 개발 편의가 크게 떨어진다. sandbox 는 루프백에만 열리므로(ADR-0021) 위험이 작다.
- **운영 화면의 출처를 목록에 넣는 것.** 운영 화면은 서버 쪽 프록시로 부르므로(ADR-0024) 브라우저 출처가 서버에 닿지 않는다. 넣을 이유가 없다.

## 결과

- 이 결정 뒤 모든 기기에서 로그아웃시키려면 그 계정의 `tokens_valid_from` 만 갱신하면 된다. 비밀번호를 바꿀 때 같은 칸을 적는 것은 이 ADR 의 범위 밖이고 후속 PRD 감이다.
- 초 단위 비교의 반대면: 로그아웃과 같은 초에 발급된 옛 토큰도 산다(QA 실측 2026-10-21, 같은 초에 로그인하고 로그아웃한 쿠키가 2초 뒤에도 200). 사람의 흐름에서는 일어나지 않고, 같은 초의 새 로그인을 살리는 대가로 받아들인다.
- 로그아웃 전에 발급된 토큰은 모두 무효가 된다. 한 기기에서 로그아웃하면 다른 기기의 세션도 끊긴다. 기기별 로그아웃은 두지 않는다. 지금 제품에 그 요구가 없다.
- production 배포 전에 환경 파일(SSM 파라미터 `/beside-pet/production/server-env`)에 `ALLOWED_ORIGINS` 를 더해야 한다. 빠지면 서버가 뜨지 않으므로 조용히 열린 채로 돌지 않는다. 안내는 `infra/docker/README.md` 에 있다.
- 대화 웹의 주소가 바뀌면(도메인, 포트) `ALLOWED_ORIGINS` 도 함께 바꿔야 한다.
