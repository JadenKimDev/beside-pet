# 발화의 화법은 코드 규칙 층이 턴마다 정한다. 지시문에 금지 목록을 넣지 않고, 모델에게 계획을 시키는 호출을 두지 않는다

## 맥락

동반자의 답이 대화 내내 같은 표현("천천히 이야기해 주셔도 괜찮아요", "제가 여기 함께 있을게요", 답 끝의 "(예: …)", 고양이에게도 "꼬리를 흔들던 모습")을 되풀이해 기계적으로 들렸다. 2026-10-19 실측(`outputs/chat-eval/2026-10-19-layers-5-5/report.md`, 로컬)에서 원인의 대부분은 발화 지시문이 그 표현을 직접 시킨 것이었다. 단계 지침마다 "Always include a short parenthetical example" 이 있었고, 첫 인사 지침이 "reassure them you are here together" 를 시켰으며, 매 답에 질문 하나를 강제했다.

같은 실측에서 층 구성 여섯 가지를 비교했다. 지시문을 고친 한 번 생성(V1)과 거기에 코드 규칙 층을 얹은 것(V6)이 가장 자연스러웠고(맹검 판정 자연스러움 4.0 → 6.0, 상투구 사전 적중 71% → 12~24%, 괄호 예시 68% → 0%), 모델에게 의도와 전술을 먼저 계획시키는 변형(V2, V3, V5)은 되받기(28~38%)와 해석 틀을 새로 만들고 1초 늦었다. 조사(`docs/research/2026-10-19-cliche-repetition-research.md`, 로컬)는 공감 대화에서 LLM 이 직전 턴의 전술을 사람의 약 두 배 비율로 되풀이하고, 외부에서 전략을 정해 주면 쏠림이 준다는 연구를 모았다. Haiku 5.5 는 temperature, top_k, 빈도 벌점을 받지 않아 샘플링 쪽 조절은 없다.

ADR-0018 은 발화 프롬프트를 "TS 문구 그대로 두고 모델이 바뀌면 그때 다시 맞춘다"고 했다. 모델이 Haiku 5.5 로 바뀐 지금(ADR-0010) 그때가 왔다. 이 ADR 이 그 항목을 잇는다.

## 결정

- **지시문은 정체와 화법만 적는다.** "warm companion" 대신 생각 깊은 사람처럼 말하고 대본처럼 말하지 않는다는 정체 문장, 1~3 문장, 사용자가 쓴 말(장소, 물건, 습관)에서 자기 말로 짓기, 시작과 끝을 바꾸기, 질문은 많아야 하나. 사용자가 말하지 않은 반려동물 세부(꼬리, 산책, 코끝)를 지어내지 않는다. 단계 지침에서 괄호 예시 필수와 "함께 있을게요"류 안심 지침을 지운다. 매 답에 질문을 강제하지 않는다. 흐름(과제, 깊이 게이트, 단계)은 그대로 코드가 정한다(ADR-0005). 문구가 통째로 바뀌므로 `REPLY_PROMPT_VERSION` 은 minor 를 올린다(ADR-0022).
- **이번 턴의 화법은 코드 규칙 층이 정한다.** `support/rules/turn_style.rs` 의 순수 함수가 단계와 세션 기록(최근 동반자 답, 최근 사용자 말)에서 `TurnStyle` 을 만들고, 흐름이 그것을 지시 한 줄("For this reply: …")로 바꿔 시스템 프롬프트 끝에 붙인다. 규칙은 넷이다. 질문 여부(Intro 는 Invite. 거부 표현, 짧은 답 두 번, 직전 답이 질문이면 Forbid. Task 는 Invite, 나머지는 Allow), 정상화 위로 쿨다운(최근 답 4개에 있었으면 다시 쓰지 않게), 같은 어미 연속 금지(직전 두 답의 끝 네 글자가 같으면 다르게 끝내게), 이미 쓴 상투구 넘기기(사전 중 이전 답에 나온 것. 사용자가 직접 쓴 낱말은 제외). `TurnStyle` 은 저장하지 않고 매 턴 기록에서 다시 구한다.
- **지시문에 금지 표현 목록과 BAD 예시를 넣지 않는다.** 상투구는 처음부터 막는 것이 아니라 "이미 쓴 것"만 넘긴다. 금지 목록은 2026-02-23 의 실측에서 13턴 중 11턴에 그대로 남았고(DEV-2026-02-23-prompt-shrink-did-not-fix-flash), 이번 실측에서도 목록으로 알리기만 한 변형(V2)은 "천천히"를 막지 못했다. 상투구 사전, 정상화 패턴, 거부 패턴은 `turn_style.rs` 한 곳에 둔다.
- **모델에게 계획(의도, 전술)을 시키는 별도 호출을 두지 않는다.** 실측에서 되받기와 해석 틀을 만들고 1초 늦었다. 지연을 더하는 층은 실측으로 이익이 보일 때만 들인다.
- **생성 뒤 다시 쓰기는 이번에 두지 않는다.** 스트림 턴은 이미 글이 나가 있다. 대신 다음 턴의 `TurnStyle` 이 지난 답들을 보고 반영한다. 다시 쓰기는 ADR-0025 의 판정기를 붙이는 살피기 층 PRD 에서 동기 턴에 한해 다시 본다.

## 버린 것

- 모델 계획 호출(V2, V3, V5): 되받기 28~38%, 지연 +1초, 새 해석 틀.
- 후보 여럿을 뽑아 사전으로 고르기(V4): 사전 적중 0% 지만 자연스러움이 V1 보다 낮았다(사전에 맞춘 최적화).
- 지시문의 금지 목록과 BAD 예시: 위의 두 실측.
- 샘플링 조절(temperature, 빈도 벌점): Haiku 5.5 가 받지 않는다.
- 반려동물의 종을 프로필에 두는 것: 종을 넘기면 개 이미지가 사라졌지만 프로필, 온보딩, 응답 모양을 웹과 함께 바꿔야 해서 다음 PRD 로 미룬다. 이번에는 "말하지 않은 세부를 지어내지 않는다"까지만 한다.

## 결과

- 지시문을 고치려는 사람은 `reply.rs` 에 금지 목록을 더하지 않고, 막고 싶은 표현을 `turn_style.rs` 의 사전에 더한다. 그러면 그 표현은 한 대화에서 한 번은 나올 수 있고 두 번째부터 넘겨진다.
- chat-eval 은 세션 안의 상투구 반복(`stockRepeat`), 되받으며 시작한 답(`echoOpening`), 정상화 위로 비율(`reassureRate`)을 함께 잰다. 기준선은 `outputs/chat-eval/haiku-5-5/2026-10-19/`(로컬)다.
- 남은 것은 문자열이 아니라 뜻의 반복("그만큼 사랑했다는 뜻이에요"류)이다. 이는 ADR-0025 의 판정기가 담당한다.
