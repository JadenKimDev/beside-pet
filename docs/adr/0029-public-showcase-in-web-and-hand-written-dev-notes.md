# 공개 쇼케이스 화면은 제품 웹에 두되 자료는 `showcase/` 에서 오고 제품 흐름에 분기는 없다. 개발 기록은 사용자의 말로 손으로 쓰는 정적 JSON 이고, 쇼케이스의 스크린샷은 삽화 규칙의 예외다

## 맥락

포트폴리오로 보여 줄 때 로그인 없이도 제품이 어떻게 동작하는지 알 수 있어야 한다. production(CloudFront 뒤의 EC2 한 대, ADR-0023)은 첫 화면이 로그인이고 `/help` 만 공개라, 계정이 없는 사람은 대화도 마음 리포트도 볼 수 없다. 루트 `CLAUDE.md` "제품 원칙"은 포트폴리오용 구현을 `showcase/` 에 두고 제품 앱에 데모 분기를 넣지 않는다고 했지만, `showcase/` 를 어디에 어떻게 띄울지는 정하지 않았다.

운영 화면에는 GitHub 이슈를 읽기 전용으로 보이는 개발노트가 있다(#33). 그것은 운영자용이고 이슈의 글은 PRD 의 글이라 사용자에게 뜻이 없다. 운영 화면은 이 머신에서만 띄운다(ADR-0024).

## 결정

- **공개 쇼케이스 화면 `/showcase` 는 제품 웹(`apps/web`)에 둔다.** `/help` 와 같은 공개 경로다(`chrome.ts` 의 PUBLIC, 인증 가드 밖, 서버 호출 없음, 서버가 내려가 있어도 열린다). 로그인 화면 머리에 "둘러보기" 링크를 둔다. 대화 코드와 서버에는 분기가 없다. "제품 앱에 데모 분기를 넣지 않는다"는 선은 **자료와 흐름**에 대한 것이고, 정적 자료를 그리는 화면 하나는 그 선을 넘지 않는다. 루트 `CLAUDE.md` 의 해당 줄을 이렇게 고친다.
- **자료는 `showcase/` 에 두고 빌드 때 웹으로 복사한다.** 스크린샷(WebP), 전사(`showcase/pomo/transcript.json`), 개발 기록(`showcase/dev-notes.json`)이 자료이고, `apps/web` 의 `prebuild`/`predev` 가 `apps/web/public/showcase/` 로 복사한다. 복사본은 gitignore 하고, 화면은 그것을 경로 문자열(`/showcase/...`)로만 가리킨다(추적 소스가 무시 파일을 가리키면 레포 검사가 실패하므로).
- **대화 자료는 지어낸 인물로 이 머신에서 만든다.** 뽀모(14살 포메라니안)와 지어낸 보호자의 대화 한 사이클을 QA 용 계정으로 sandbox 에서 돌려 스크린샷과 전사를 남긴다. 실제 사용자의 대화는 쓰지 않는다(루트 `CLAUDE.md` "지키는 선"). 전사 파일 머리에 지어낸 것이라고 적고, 화면도 그렇게 알린다.
- **개발 기록은 사용자의 말로 손으로 쓰는 정적 JSON 이다.** 항목은 `{ date, kind, title, body, issue }` 이고 `kind` 는 버그 고침 / 새 기능 / 개선 / 진행 중 넷이다. `issue` 는 내부 추적용이고 화면에 보이지 않는다. 글은 기능 이름이 아니라 "이렇게 달라졌어요"로 쓰고, 코드 이름, 테이블, 환경 변수, 이슈 번호, GitHub 링크를 쓰지 않는다. ADR-0003 의 금지어 규칙이 그대로 적용되고 레포 검사가 모양과 금지어와 코드 이름 꼴(백틱, 대문자 환경 변수, `#숫자`, github.com)을 본다. 쓰는 때는 이슈 마감이다(`implement-prd` 마감 절차의 한 항목). `planned`(진행 중)는 열린 이슈 가운데 사용자에게 보일 것만 PRD 를 올릴 때 한 항목으로 두고, 끝나면 종류와 날짜를 고친다.
- **쇼케이스의 스크린샷은 삽화 규칙의 예외다.** `apps/web/CLAUDE.md` 는 글자가 든 이미지를 넣지 않는다고 하지만, 스크린샷은 삽화가 아니라 제품 화면의 기록이다. 같은 글이 이미지 밖(전사)에 늘 있으므로 뜻은 이미지에 기대지 않는다. 자리는 `public/showcase/`(복사본)이고 `public/illustrations/` 가 아니다.

## 버린 것

| 안 | 이유 |
|---|---|
| CloudFront 뒤 S3 정적 사이트로 따로 올림 | 인프라 변경과 두 번째 배포 경로가 생긴다. 쇼케이스 하나를 위해 Pulumi 와 배포 스크립트를 늘릴 이유가 없다 |
| 런타임에 GitHub API 를 불러 개발 기록을 만듦 | 토큰이 공개 웹에 들어가거나 서버 호출이 생긴다. 이슈의 글은 PRD 의 글이라 사용자에게 뜻이 없고, 쉬운 말로 옮기는 일은 사람이 해야 한다 |
| 운영 화면의 개발노트(#33)를 공개로 돌림 | 운영 화면은 이 머신에서만 띄우고(ADR-0024) 글도 운영자용이다 |
| 쇼케이스 자료를 `apps/web/public/` 에 직접 추적 | 포트폴리오용 자료가 제품 앱 안에 들어온다. `showcase/` 에 두면 "제품은 `apps/`, 포트폴리오는 `showcase/`" 선이 그대로 남는다 |
| 데모 계정으로 실제 대화 화면을 공개 | 모델 호출 비용과 남용의 문제가 있고, 제품 흐름에 데모 분기가 생긴다 |

## 결과

- 루트 `CLAUDE.md` "제품 원칙"의 첫 줄과 구조 표의 `showcase/` 행이 바뀐다. `apps/web/CLAUDE.md` 의 "공개 경로"와 "삽화" 규칙에 `/showcase` 와 스크린샷 예외가 들어간다.
- `implement-prd` 스킬의 마감 절차에 "개발 기록 한 항목을 더한다(사용자에게 보이는 변화가 없으면 생략)"가 들어간다.
- 사용자의 테마를 바꾸면 스크린샷을 다시 찍어 바꿔야 한다(자료는 찍은 시점의 모습이다).
